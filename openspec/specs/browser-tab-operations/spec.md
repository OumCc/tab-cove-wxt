# 浏览器标签操作规范

## 审阅摘要

- 在工作台查看和操作 Chrome 窗口、标签及原生标签组，可将会话保存到本地收藏，也可从收藏恢复。
- 验收覆盖目录同步、跨窗口移动、固定标签保护，以及保存、打开和分组失败时的反馈。

## Purpose

定义实时标签目录、原生组管理以及浏览器会话与本地收藏之间的保存和恢复行为。保存成功后才可按用户选择关闭源标签，恢复部分失败时保留原收藏。

## Requirements

### Requirement: 实时窗口标签目录

系统 SHALL 按真实窗口、标签顺序和原生标签组组织 Open Tabs，并响应标签创建、关闭、导航、移动、激活、跨窗口迁移及组创建、更新、删除事件。所有 `chrome-extension://` 插件页面及正跳转至插件页面的标签 MUST 从目录、目录计数和会话快照中排除。

#### Scenario: 浏览器发生变化

- **WHEN** 用户在 Chrome 中改变标签标题／URL、跨窗口移动标签或重命名原生组
- **THEN** 工作台更新对应条目、顺序和组信息，不需要刷新页面，已保存收藏不被自动改写。

#### Scenario: 排除浏览器插件页面

- **WHEN** 窗口包含 Tab Cove、其他插件页面，或某个标签的 pendingUrl 指向 `chrome-extension://`
- **THEN** 这些标签不显示于 Open Tabs，不计入目录标签数量，也不进入保存会话快照；普通网页及 `chrome://` 浏览器内置页面仍遵循原有显示规则。

#### Scenario: 激活或关闭实时标签

- **WHEN** 用户在 Open Tabs 选择激活或关闭一个标签
- **THEN** 对应真实标签被激活并聚焦窗口，或被关闭；已不存在的标签产生可理解的反馈并刷新目录。

### Requirement: 保存窗口会话

系统 SHALL 将指定窗口的可保存非固定标签按浏览器顺序保存到新集合或追加到指定集合，并提供保存后保持打开与保存后关闭两种明确选择。

#### Scenario: 新建会话集合

- **WHEN** 用户对包含普通标签和固定标签的窗口选择保存会话
- **THEN** 普通可保存标签按顺序进入集合，固定标签不被保存或关闭；新集合提供日期时间名称并可修改。

#### Scenario: 追加已有集合

- **WHEN** 用户选择把窗口标签保存到一个已有集合
- **THEN** 原有卡片不变，新卡片按浏览器顺序追加到末尾；不隐式去重。

#### Scenario: 没有可保存标签

- **WHEN** 选定窗口没有可保存非固定标签
- **THEN** 提示没有可保存内容，不创建空会话集合，也不关闭窗口。

### Requirement: 先持久化再关闭

系统 MUST 在本地保存成功后才执行用户选择的关闭源标签操作；关闭失败不撤销已保存收藏，保存失败不得关闭源标签。

#### Scenario: 本地存储失败

- **WHEN** 保存会话时本地写入被拒绝
- **THEN** 显示保存失败，全部源标签保持打开，界面不宣称保存成功。

#### Scenario: 保存后部分关闭失败

- **WHEN** 收藏已写入，但部分源标签无法关闭或已导航到不同 URL
- **THEN** 保留收藏，报告未关闭的标签；已经导航到其他页面的标签不被关闭，刷新实时列表供用户处理。

### Requirement: 打开和恢复收藏

系统 SHALL 按集合中的卡片顺序打开集合，可恢复为普通标签或命名原生标签组；恢复不会移除本地收藏，也不会关闭既有浏览器页面。

#### Scenario: 普通恢复

- **WHEN** 用户选择打开整个集合为普通标签
- **THEN** 其 URL 按收藏顺序打开，重复 URL 仍按收藏中的条目数量打开，本地集合不变。

#### Scenario: 部分恢复失败

- **WHEN** 部分 URL 创建标签失败，或新标签创建后原生分组失败
- **THEN** 已创建标签保留，本地收藏完整保留；明确区分未打开的链接与仅分组失败，不通过重新打开整个集合制造额外重复页。

### Requirement: 原生标签组保存与恢复

系统 SHALL 支持把 Chrome 原生标签组保存为集合，并在组恢复时保留保存的名称、颜色及成员顺序；永久收藏不依赖旧 groupId。

#### Scenario: 保存一个组

- **WHEN** 用户保存名为“研究”、颜色为蓝色的原生组
- **THEN** 新集合以该组名称和颜色元数据记录成员 URL 及顺序，并按用户选择保持或关闭该组的源标签。

#### Scenario: 浏览器重启后恢复组

- **WHEN** 浏览器已重启，用户将保存的组集合恢复为原生组
- **THEN** 使用新的浏览器标签及 groupId，恢复保存的名称、蓝色和成员顺序，旧标识不参与恢复。

### Requirement: 原生组管理

系统 SHALL 在工作台中支持原生组名称、Chrome 支持的颜色、折叠状态和取消分组，以及将实时标签拖入或拖出原生组；这些操作作用于真实浏览器。

#### Scenario: 编辑与取消分组

- **WHEN** 用户改名、换色、折叠或取消一个原生组
- **THEN** Chrome 和 Open Tabs 展示同样结果；取消分组只移除分组关系，不关闭标签、不删除收藏。

#### Scenario: 跨窗口拖动组成员

- **WHEN** 用户将一个实时标签拖入另一窗口的组或拖到未分组位置
- **THEN** 浏览器移动并按目标更新分组关系及位置；失败时重新读取真实状态，不能仅在 UI 显示已移动。

### Requirement: 拖入收藏与拖回浏览器

系统 SHALL 支持将实时标签拖入收藏集合，以及将收藏卡片拖入指定浏览器窗口或原生组；保存和打开遵循同一数据安全规则。

#### Scenario: 实时标签拖入集合

- **WHEN** 用户将 Open Tabs 中的一个标签拖到集合指定位置
- **THEN** 在本地写入该标签快照，并明确提供保持打开／保存后关闭的选择；取消时不修改收藏或浏览器。

#### Scenario: 收藏拖回实时区域

- **WHEN** 用户将收藏卡片拖到 Open Tabs 的窗口或组落点
- **THEN** 在指定位置打开对应 URL，必要时加入目标组，原收藏仍保留。
