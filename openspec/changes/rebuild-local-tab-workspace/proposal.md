# 变更提案

## 审阅摘要

- 为什么做：现有项目停留在账号、团队和集合列表框架，尚不能完成保存、整理和恢复标签的闭环。
- 目标结果：使用现有技术栈，交付参考 Toby Mini 2.0 的单机工作台，从插件图标打开，直接管理空间、集合、浏览器标签及原生标签组。
- 范围：空间／集合／卡片管理、搜索、拖拽、会话保存恢复、原生标签组、本地持久化。Q-008 所列附加功能后续再做。
- 验收：真实 Chrome 中完成普通窗口和标签组保存、关闭、重启、恢复；数据与顺序正确；失败不丢收藏；公开基准布局核对通过，并由用户完成 Toby Mini 实物对照。
- 风险：扩展页面工具访问受限，不能自动完成实物验收；浏览器操作和本地存储不是同一事务，必须单独处理保存成功后的关闭／分组失败。

## 已确认变化

1. 首次打开直接进入本地工作台，移除创建账号、团队和权限流程。
2. 采用一个本地资料库，以 Space → Collection → SavedTab 组织收藏；右侧显示浏览器实时窗口、标签和原生组。
3. 点击插件图标打开或聚焦独立页面，Chrome 新标签页及现有新标签插件继续正常工作。
4. 保存窗口或标签组到新集合或已有集合；保存时明确选择是否关闭源标签。保存与关闭顺序保证本地写入失败时标签仍在。
5. 从集合打开链接或恢复整个集合，可恢复为原生标签组；本地收藏不随浏览器关闭而消失。
6. 通过搜索、集合折叠、拖拽排序、跨集合移动、集合合并及原生组操作整理标签。

## 范围

### 范围内

- 浅色三栏布局、卡片展示、空间和集合计数、空态、加载、操作确认及错误反馈。
- 空间和集合的新建、重命名、删除、排序；卡片标题／URL 编辑、打开、移除与移动。
- 窗口和原生组中的实时标签展示、激活、关闭与移动；原生组名称、颜色、折叠、取消分组。
- 新建／追加保存，普通标签／原生组恢复，按顺序打开，固定标签不纳入整窗保存。
- 本地全文本匹配搜索，按空间、集合、已保存标签、已打开标签分类；快捷键与可取消拖拽。
- 单一写入边界、版本化本地存储和跨页面刷新；有意义的数据及浏览器适配测试。

### 范围外

- 登录、账号、成员、团队角色、权限分级、共享、同步、云端服务、订阅、配额计费、统计上报。
- Next、To/Links、AI、独立笔记、浏览器历史检索、popup、浏览器侧边栏、新标签页接管。
- 星标、集合自定义颜色、Tags、备注、视图切换、去重、主题切换、导入导出和旧数据迁移；原生组颜色作为必要元数据保留。
- 页面正文、表单、登录态、滚动位置和单标签前进后退历史的“现场恢复”；本轮恢复 URL、标题、顺序和明确保存的组元数据。
- Firefox、移动端、商店上架、自动发布、Git 提交。

## 能力清单

### 新增能力

- `local-tab-workspace`：三栏本地工作台、空间与集合管理、收藏卡片、搜索及拖拽。
- `browser-tab-operations`：实时窗口与标签、Chrome 原生组、保存和恢复会话、浏览器操作失败反馈。
- `local-persistence`：离线资料库、稳定标识、单写入队列、跨页面一致性和失败保护。

### 修改能力

无已有 OpenSpec 能力。本次重建现有未完成业务骨架，不把旧账号／团队模型定义成需要向后兼容的产品契约。

## 影响

### 行为与用户

无需注册即可使用。保存后的收藏与浏览器实时页面各自独立，删除收藏不会顺带关闭实时页面；关闭实时页面不会删除收藏。已排除模块不保留空按钮。

### API 与依赖

不增加后端 API。沿用 WXT 浏览器封装、扩展消息库和本地存储；使用 Chrome tabs/windows/tabGroups API。继续使用 pnpm，初始方案不新增运行时依赖；拖拽使用浏览器原生机制，测试使用当前 Node 工具链。

### 代码与运行

替换现有团队领域和工作台 UI，保留入口地址并扩展后台的浏览器事件及命令处理。新版资料库与旧数据隔离，不执行清空存储；具体修改地图见 design.md。
